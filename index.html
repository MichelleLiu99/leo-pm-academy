CHAPTER 01

衛星通訊基礎

先了解低軌衛星與終端機的角色，以及它和一般地面網路的差異。

🛰 什麼是 LEO？

LEO（Low Earth Orbit）指低地球軌道，常見高度約 300–2,000 公里。因衛星相對地面快速移動，終端機可能需要動態波束追蹤與衛星切換。

📡 什麼是 User Terminal？

地面的衛星通訊設備，用來與衛星建立無線鏈路，將網路連到使用者設備、企業內網或其他資料設備。

典型網路連線路徑

💻 使用者設備電腦／工業設備／路由器
↕
📡 LEO User Terminal天線 + RF + 數據機／控制
↕ 無線衛星鏈路
🛰 LEO Satellite提供衛星連線／轉送
↕
🌐 Gateway／衛星網路連接 Internet 或企業專網

註：部分星系使用衛星間鏈路（ISL）轉送，不一定立即經過地面 Gateway。

軌道類型大致高度PM 理解重點
LEO 低軌約 300–2,000 km相對地面移動快、低延遲、需要追蹤／切換策略
MEO 中軌約 2,000–35,786 km常見於衛星導航等用途
GEO 地球靜止約 35,786 km在地面觀察下大致維持固定方向

💡 PM 的第一個任務

確認你的專案交付範圍究竟是 天線模組（Antenna Module）、終端機（User Terminal），或完整通訊系統（Communication System）。這會決定你要追蹤的模組與驗收責任。

CHAPTER 03

技術術語字典

把英文縮寫轉換成你能用在會議中的工作語言。支援搜尋與分類。

找不到符合的術語，試試英文或中文關鍵字。

四個必須優先搞懂的 RF 指標

EIRP｜發射能力特定方向的等效全向輻射功率，單位常見 dBW／dBm。
G/T｜接收性能接收天線增益與系統雜訊溫度之比，單位常見 dB/K。
Beamforming｜波束成形控制多個天線單元的訊號，讓能量朝目標方向集中。
Link Budget｜鏈路預算綜合功率、天線增益、距離與各種損耗，判斷連線餘裕。
CHAPTER 04

硬體開發與測試流程

從需求、樣機、工程驗證到試產量產，理解各階段如何決定是否可以往下一步。

Requirements／Feasibility

確認產品需求、規格、驗收準則與技術可行性；產出 PRD／System Spec。

Design／Prototype

設計模組、建立工程樣機，進行初步功能與整合測試。

EVT｜Engineering Validation Test

驗證核心設計可行性，收斂重大技術問題。

DVT｜Design Validation Test

確認設計符合正式規格、可靠度、環境與其他測試要求。

PVT｜Production Validation Test

確認生產流程、測試治具、組裝及良率能支援量產。

MP｜Mass Production

量產交付、品質監控、成本與工程變更管理。

開發流程名稱和 Gate 的通過條件依公司及客戶要求而異，部分測試也可能平行進行。

RF／OTA Test

發射／接收性能、波束指向、掃描角度等測試。

Thermal／Environmental

高低溫、工作負載、可靠度與環境條件測試。

Integration Test

天線、RF、FW、Modem 與整體鏈路整合驗證。

範例：規格沒有達標時，PM 如何追？

假設要求 EIRP ≥ 40 dBW，實測 38.5 dBW，差距為 1.5 dB（純教學虛構數字）。

  1. 確認測試頻率、角度、溫度、版本及樣本數。
  2. 釐清是否已確認根因、是否有跨模組依賴。
  3. 記錄 Owner、改善措施、重新驗證日期。
  4. 估算對下一 Milestone 的影響並依權責升級。

未達標不代表一定無法使用；能否放行應依正式規格及核准流程判斷。

CHAPTER 05

工程會議情境練習

工程師提出問題時，學會把技術敘述轉成可追蹤的 Action Item。

5W + Impact 萬用追問法

What問題／規格差距是什麼？
Why根因或待驗證假設？
Who負責工程團隊／Owner？
When何時有下一次可驗證結果？
How改善方案與重測方式？
Impact影響交期、成本或範圍嗎？

PM 可以追問

    會議結束前取得

    向主管報告用四段式

    Progress：已完成什麼、距離下一里程碑有多遠？

    Issue：主要差距或阻礙是什麼？

    Action：誰負責、何時提出改善／驗證結果？

    Impact：是否影響時程、成本或品質，需要什麼決策？
